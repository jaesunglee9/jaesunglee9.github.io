Programmers 42883 — Make the Largest Number (C++)

Problem

This is a summary of the original problem. See the source link for the full statement.

Remove exactly k digits from the numeric string number while preserving the relative order of the remaining digits. Return the largest possible number as a string.

Interface and constraints

  • Function: string solution(string number, int k)
  • number contains between 2 and 1,000,000 digits.
  • k is at least 1 and less than the length of number.

Examples

number k return
"1924" 2 "94"
"1231234" 3 "3234"
"4177252841" 4 "775841"

Solution

#include <string>
#include <vector>

using namespace std;

string solution(string number, int k) {
    string answer = "";        
    for (auto ch : number) {
        while (answer != "" && k > 0 && answer.back() < ch) {
            answer.pop_back();
            k--;
        }
        answer += ch;
    }

    while (k > 0) {
        answer.pop_back();
        k--;
    }

    return answer;
}

Approach

This problem took me some time.

Positional weight

For two \(L\)-digit numbers, the first differing digit from the left determines which number is larger.

\[ A = \overline{a_1 a_2 \dots a_L}, \qquad B = \overline{b_1 b_2 \dots b_L} \]

If the first differing position is \(i\) and \(a_i > b_i\), then \(A > B\), regardless of the remaining digits. The smallest difference at that position exceeds the largest possible difference across all later positions.

\[ (a_i - b_i) \cdot 10^{L-i} \ge 10^{L-i} > \sum_{j=i+1}^{L} 9 \cdot 10^{L-j} = 10^{L-i} - 1 \]

With a fixed number of digits to retain, making an earlier digit larger takes priority over improving later digits.

The general base-and-length conditions and suffix bound are developed in Positional weight and lexicographic order.

Removing the smaller preceding digit (Exchange argument)

Consider adjacent digits \(x, y\) with \(x < y\), while we still have deletions available. Removing \(x\) moves the larger digit \(y\) into its position.

\[ \dots x y \dots \;\longrightarrow\; \dots y \dots \]

The positional-weight observation motivates this greedy choice. This solution uses answer as a stack, popping trailing digits smaller than the incoming digit while deletions remain.

Greedy digit deletion with a monotonic stack explains how the deletion budget bounds the next choice, why the earliest maximum is safe, and why remaining deletions are taken from the end. Its monotonicity condition applies while deletions remain; the final output need not be monotone.

Remarks

Positional weight and the exchange argument support greedy reasoning here. Invariants are useful beyond greedy algorithms too: when reasoning about another algorithm, ask what must remain true after each step.
