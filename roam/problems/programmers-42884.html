programmers-42884 — Speed Cameras (단속카메라)

Source

Programmers 42884 — 단속카메라

Problem

English summary of the linked problem: each vehicle travels along a highway from its entry position to its exit position. Given these routes, return the minimum number of cameras needed so that every vehicle encounters at least one camera along its route.

Constraints

  • There are between 1 and 10,000 vehicles.
  • routes[i][0] is vehicle i's entry position; routes[i][1] is its exit position.
  • A camera at either endpoint counts as an encounter.
  • Entry and exit positions range from -30,000 to 30,000, inclusive.

Example

routes return
[[-20,-15], [-14,-5], [-18,-13], [-5,-3]] 2

Cameras at -15 and -5 cover all four vehicles: the first covers the first and third routes, and the second covers the second and fourth routes.

Solution

#include <vector>
#include <algorithm>

using namespace std;

int solution(vector<vector<int>> routes) {
    sort(routes.begin(), routes.end(), [](const vector<int>& a, const vector<int>& b) {
        return a[0] < b[0];
    });

    int answer = 1;
    int limit = routes[0][1]; 

    for (const auto& r : routes) {
        if (r[0] > limit) {
            answer++;
            limit = r[1]; 
        } else {
            limit = min(limit, r[1]);
        }
    }
    return answer;
}

Approach

#include <string>
#include <vector>

bool check_overlap(vector<int>& range1, const vector<int>& range2) {
    if (range1[1] < range2[0]) {
        range1 = range2;
        return false;
    }
    else {
        range1 = {range2[0], range1[1]};
        return true;
    }
}

int solution(vector<vector<int>> routes) {
    int answer = 0;
    sort(routes.begin(), routes.end(), [](const vector<int>& a, const vector<int>& b) {
        return a[0] < b[0];
    });
    vector<int> range = {-90000, -60000};
    for (const auto& r : routes) {
        bool overlap = check_overlap(range, r);
        if (overlap == false) answer++; 
    }
    return answer;
}

This was my original solution. Note that the entire range is being carried around, along with some redundant state.

Remarks

I couldn't state a convincing argument why I should sort beforehand, other than that it works. My intuition is that it allows for invariance, but I don't know what that is.

After some thinking, I can state the reason. Let us consider the common intersection of current routes as range R and the next route A. Let us compare two cases: one where the routes are sorted by entry position, and one where they are not. In the sorted case, if A does not overlap with R, then we can deduce that no remaining route can overlap with R, since all remaining routes have entry positions greater than or equal to A's. So we can stop, set A as the new R, and begin again. In the unsorted case, after comparing with A, we cannot make the same deduction about the rest of the routes.

To sum up, sorting allows us to consider the set of routes as three partitions: processed, currently being processed, and unprocessed. Processing the current route allows us to infer properties about the unprocessed partition.

Other than that, I know that the optimized version is shorter, but I dislike the formulation of the problem as a whole. For example, when we solve this problem, we are generally expected to find the range where we should install cameras, as well as the number of cameras. I find the detachment of real use cases from algorithmic problem solving somewhat not to my taste.
