Programmers 42895 — N으로 표현

Problem

English summary of the linked problem: given a digit N and a target number, return the minimum number of occurrences of N needed to express the target. You may concatenate copies of the digit, use parentheses, and apply addition, subtraction, multiplication, and division. Division discards the remainder. If the minimum exceeds eight occurrences, return -1.

Constraints

  • 1 < N <= 9=
  • 1 < number <= 32000=
  • Expressions may use parentheses and the four arithmetic operations, with repeated copies of N forming numbers such as 55 when N = 5.

Examples

N number Return
5 12 4
2 11 3

For the first example, (55 + 5) / 5 expresses 12 using four copies of 5. For the second, 22 / 2 expresses 11 using three copies of 2.

Solution

#include <string>
#include <vector>
#include <unordered_set>

using namespace std;

int solution(int N, int number) {
    int answer = 0;
    vector<unordered_set<int>> dp(9);

    int tmp = 0;
    for (int i = 1; i < 9; i++) {
        tmp = tmp * 10 + N;
        dp[i].insert(tmp);
    }

    for (int k = 1; k<9;k++){
        for (int i = 1; i < k; i++) {
            int j = k - i;
            for (int a : dp[i]) {
                for (int b : dp[j]) {
                    dp[k].insert(a+b);
                    dp[k].insert(a-b);
                    dp[k].insert(a*b);
                    if (b != 0) dp[k].insert(a/b);
                }
            }
        }

        if (dp[k].count(number) != 0) return k;
    }


    return -1;
}

Approach

I originally thought the number of possibilities would grow exponentially and make this approach infeasible. I was thinking of \(9^8=3^{16}\), but that estimate does not count the combinations this implementation actually processes.

This is dynamic programming over sets of reachable values. dp[k] stores the distinct integers expressible with exactly k copies of N. Repeated-digit numbers such as 55 are inserted first. For every split k = i + j, the code combines values from dp[i] and dp[j] using the four operations, skipping division by zero. Different expressions that produce the same value share one set entry. The target is checked as the number of copies increases.

Remarks

Values, states, and work are different quantities

\(N^8\) can be a value in dp[8] because eight copies of N can be multiplied together. It is not the number of elements in that set. For example, a set containing 1 and 1,000,000 still stores only two elements. The digit N is fixed for a run; it is not a branching factor of nine at every step.

The useful question is how many distinct values each layer stores and how many pairs of those values are combined. Duplicate expressions still cause insertion attempts, but duplicate results do not create extra states for later combinations. A large-looking count of possible expressions is therefore not automatically the program's state count or operation count.

Time and space in terms of stored states

Let \(K\) be the maximum number of copies, here 8, and let \(S_k=|dp[k]|\). For a split \(k=i+(k-i)\), the nested loops visit \(S_iS_{k-i}\) pairs. Each pair attempts at most four insertions. Assuming fixed-width arithmetic and amortized expected constant-time hash operations, the time through layer \(K\) is

\[ O\left(K+\sum_{k=2}^{K}\sum_{i=1}^{k-1}S_iS_{k-i}\right). \]

All layers remain stored, so space is

\[ O\left(K+\sum_{k=1}^{K}S_k\right). \]

With \(S=\max_{1\le k\le K}S_k\), looser bounds are \(O(K^2S^2)\) time under the same hash assumption and \(O(KS)\) space. These expressions do not establish that the sets grow polynomially with \(K\); they expose the state sizes on which the work depends. An earlier return stops before all eight layers are combined.

\(3^{16}=43{,}046{,}721\), but this is not a derived operation count for this implementation. Whether millions of operations are practical also depends on what each operation does; hash insertions cost more than simple additions. No set sizes or runtimes were measured here.
