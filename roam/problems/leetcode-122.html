LeetCode 122 — Best Time to Buy and Sell Stock II

Problem

Summary of the linked problem: prices[i] gives a stock's price on day i. Choose when to buy and sell to maximize total profit. You may make multiple transactions, including selling and buying again on the same day, but may hold at most one share at any time. Return the maximum achievable profit.

Constraints

  • 1 < prices.length <= 3 * 104=
  • 0 < prices[i] <= 104=

Examples

prices Output
[7,1,5,3,6,4] 7
[1,2,3,4,5] 4
[7,6,4,3,1] 0

In the first example, buying at 1 and selling at 5 earns 4; buying at 3 and selling at 6 earns another 3. In the second, buying at 1 and selling at 5 earns 4. In the third, making no transactions earns 0.

Solution

#include <vector>

using namespace std;

class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int profit = 0;

        for (int i = 1; i < prices.size(); ++i) {
            if (prices[i] > prices[i - 1]) {
                profit += (prices[i] - prices[i - 1]);
            }
        }

        return profit;
    }
};

Approach

class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int profit = 0;
        int s = 0;
        while (s < prices.size()) {
            // check for ascending range
            int e = s + 1;
            while (e < prices.size() && prices[e] >= prices[e-1]) {
                e++;
            }
            // if range is 1 (is descending) s should be incremened
            if (e - s == 1) {
                s++;
            }
            // else (there exists nonzero range) add to profit the possible thing, set s to e + 1
            else {
                profit += (prices[e-1] - prices[s]);
                s = e;
            }
        }

        return profit;
    }
};

Initial code. Quite ugly, and clunky. Don't overthink it.

Remarks

A non-decreasing stretch's endpoint gain equals the sum of its adjacent gains: \(p_b-p_a=\sum_{i=a+1}^{b}(p_i-p_{i-1})\). For prices 1, 3, 5, holding from 1 to 5 earns 4, and the adjacent gains are 2 + 2 = 4. Explicitly finding the stretch's endpoints is unnecessary when the desired total can be accumulated from adjacent changes.

This greedy formulation depends on the trading rules: there is no transaction fee, cooldown, or limit on the number of transactions. Those restrictions could couple decisions across days, so the same simplification would need a new justification.
