Positional weight and lexicographic order

For digit strings of the same length and base, numerical order agrees with lexicographic order: the first unequal digit from the left decides which value is larger. A one-unit advantage at that position outweighs every possible disadvantage in the suffix.

For example, 4000 is greater than 3999. Increasing the thousands digit by one adds 1000, while changing the entire remaining suffix can contribute at most 999.

Why the first difference dominates

Let the base be \(b \ge 2\), and let \(A=a_1\dots a_L\) and \(C=c_1\dots c_L\) contain digits from \(0\) to \(b-1\). Their positional values are

\[ V(A)=\sum_{j=1}^{L} a_j b^{L-j}, \qquad V(C)=\sum_{j=1}^{L} c_j b^{L-j}. \]

Suppose the first unequal position is \(i\), with \(a_i>c_i\). The equal prefix contributes nothing to \(V(A)-V(C)\). The advantage at position \(i\) is at least \(b^{L-i}\), while the largest possible disadvantage from later digits is

\[ \sum_{j=i+1}^{L}(b-1)b^{L-j}=b^{L-i}-1. \]

Therefore,

\[ V(A)-V(C)\ge b^{L-i}-(b^{L-i}-1)=1>0. \]

This includes the last-position case: the empty suffix contributes zero. Swapping \(A\) and \(C\) proves the reverse case, and identical strings have identical values. Thus numerical and lexicographic comparisons give the same ordering on these fixed-length digit strings.

Conditions and use

The digit comparison must follow numerical digit order, and all candidates must use the same base and length. Leading zeros are allowed when those conditions hold. Different lengths break the equivalence: "9" follows "10" lexicographically, although \(9<10\).

When an optimization keeps exactly \(L\) digits, compare candidate strings directly instead of converting them into integers. An improvement at the earliest differing position takes priority over the entire suffix. This identifies the objective; a greedy algorithm must still show that each chosen prefix admits a feasible completion.

In Make the Largest Number, deleting exactly \(k\) digits fixes the output length at \(N-k\). The greedy digit-deletion argument uses this ordering together with the deletion budget to justify which digit can be chosen next.

Reference: the C++ working draft's lexicographical-comparison definition specifies comparison by the first unequal pair, with a shorter proper prefix preceding the longer sequence. The positional-value argument above explains why that comparison also orders equal-length digit strings numerically.
