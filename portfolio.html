이재성

백엔드, 인프라, AI 에이전트

서비스가 실제 환경에서 안정적으로 동작하도록 만드는 일을 합니다. 기능을 만든 뒤에도 데이터가 어긋나지 않는지, 권한이 필요 이상으로 넓지 않은지, 결과를 믿을 수 있는지까지 확인합니다.

Olim: 배포 자동화 플랫폼

SW마에스트로, 3인 팀, 백엔드와 인프라 담당 (Kotlin, Spring Boot, AWS EKS)

사용자의 코드 저장소를 분석해 애플리케이션을 빌드하고 쿠버네티스에 배포하는 서비스입니다.

재배포할 때 사용자 설정이 사라지는 문제

문제
자원 사양과 환경변수가 코드 분석 결과에 묶여 있어, 새 커밋으로 다시 분석하면 설정이 이어지지 않았습니다.
한 일
설정을 서비스 단위로 저장하도록 구조와 API를 바꾸고, 실행 의도 상태와 배포 및 롤백 이력을 분리했습니다.
결과
재배포 시 직전 설정을 그대로 이어받음.

운영과 스테이징 권한 분리

문제
운영과 스테이징이 같은 AWS 계정에 있어, 시험 작업이 운영 자원에 영향을 줄 수 있었습니다.
한 일
배포 역할을 환경별로 나누고 OIDC 조건으로 브랜치별 사용 범위를 제한했습니다. 스테이징 역할에는 운영 EKS, RDS, 시크릿에 대한 명시적 거부를 넣은 뒤, 스테이징을 별도 계정으로 옮기고 SCP로 운영 권한을 제한했습니다.
결과
개발 권한으로 운영 자원과 기록을 바꿀 수 없는 구조.

장애 대응 AI 에이전트의 판단 검증

문제
정상적으로 반환된 응답만 보면 에이전트의 실패를 놓칩니다.
한 일
조회와 변경 권한을 나누고 Kubernetes RBAC로 실행 범위를 제한했습니다. Python 평가 모듈을 만들어 잘못된 서비스 선택, 오탐, 시간 초과를 구분해 평가했습니다.
결과
정확성과 처리 완료 여부를 따로 보는 평가 기준 마련.

팀 간 API 변경 누락

문제
서버와 프론트엔드를 별도 저장소에서 개발하면서 API 변경이 제때 공유되지 않아 화면 오류가 났습니다.
한 일
코드에서 생성한 OpenAPI 명세를 저장소에 함께 두고, 저장된 명세와 다르면 CI에서 실패하도록 했습니다. 로그와 분산 추적(OpenTelemetry, Loki, Tempo)으로 서비스 간 요청 흐름도 확인할 수 있게 했습니다.
결과
API 변경이 리뷰 단계에서 드러나도록 절차화.

똑띠: 산업안전 AI 서비스

SKT FLY AI Challenger, 백엔드와 인프라 담당 (VLM, RAG, Azure)

현장 영상에서 위험 상황을 분석하고, 관련 안전 규정을 찾아 보고서를 만드는 서비스입니다.

실시간 영상 분석 지연 3초에서 0.7초 미만으로

문제
영상을 계속 클라우드로 보내는 구조라 위험 알림이 약 3초 늦었습니다.
한 일
구간별 시간을 측정해 전송 병목을 확인했습니다. 현장 기기의 경량 YOLO가 의미 있는 변화를 감지할 때만 분석을 요청하게 바꾸고, 서버는 수신과 분석을 비동기로 분리했으며, 메모리 압축으로 반복 입력을 줄였습니다.
결과
응답 지연 0.7초 미만, 긴 영상에서도 문맥 유지.

제한된 예산 안에서 GPU 개발 환경 마련

한 일
RTX 4090 노트북을 팀 공용 서버로 구성하고 Tailscale과 JupyterHub로 원격 사용 환경을 만들었습니다. GitHub Actions와 Azure로 CI/CD를 구축해 팀원 기능을 배포 환경에서 바로 확인하게 했습니다.

AI 에이전트 개발 워크플로

팀 개발 방식 개선 (Claude Code, MCP, Jira, Confluence)

회의 결정을 문서와 업무 티켓까지 연결

문제
작업 범위가 자주 바뀌면서 회의 결정이 문서에 늦게 반영되거나 이전 결정과 충돌했습니다.
한 일
회의 녹음을 로컬 음성 인식으로 회의록으로 만들고, 에이전트가 팀 문서와 대조해 Jira 티켓으로 나누게 했습니다. 판단 순서(과거 결정, 코드, 티켓 이력)를 정하고, 정해진 범위 밖의 작업은 hook으로 막았으며, 팀이 검토한 뒤에만 티켓을 만들게 했습니다.
결과
도입 전후 4주 비교, 완료 티켓 약 50% 증가.
