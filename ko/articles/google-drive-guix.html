리눅스에서 Google Drive 마운트하기

Google Drive를 리눅스의 폴더처럼 쓰고 싶은 분들에게 이 글이 도움이 되면 좋겠습니다. 원격 접근용 MCP도 있는 것으로 알고 있지만, 쓰기 번거롭고 느립니다. 반면 폴더로 직접 마운트하는 방식은 훨씬 위험합니다. 매일 자동으로 백업해 두기를 강력히 권합니다. 한 시간마다 하는 것도 고려할 만합니다.

저는 Guix System을 사용하지만, 아래 방법은 대부분의 리눅스 배포판에서도 쓸 수 있을 것입니다.

설정은 두 단계입니다. 먼저 rclone에 Drive 접근 권한을 주고, 그다음 폴더에 마운트합니다. 권한을 주는 것만으로 로컬 폴더가 생기지는 않습니다.

설치하고 확인하기

배포판의 패키지 관리자로 rclone을 설치하거나 공식 설치 안내를 따릅니다. 설치한 버전이 rclone mount 를 지원하는지, FUSE를 사용할 수 있는지 확인합니다.

Guix에서는 처음에 다음 명령으로 패키지를 설치했습니다. 

guix install rclone restic
rclone version
restic version

Guix를 쓴다면 이 패키지들을 Guix Home 설정에 넣는 것도 고려해 볼 만합니다.

내 Google OAuth 클라이언트 사용하기

rclone의 클라이언트 ID 안내에 따라 설정합니다.

  1. Google Cloud 프로젝트를 만들거나 기존 프로젝트를 선택하고, Google Drive API를 활성화합니다.
  2. OAuth 브랜딩, 연락처 이메일, 대상 사용자, 데이터 접근 권한을 설정합니다.
  3. 개인용 외부 앱을 Testing 상태로 쓴다면 내 계정을 테스트 사용자로 추가합니다.
  4. Desktop app 유형의 OAuth 클라이언트를 만들고, ID와 비밀 키를 보관합니다.
  5. 사람이 지켜보지 않고 실행해 두려면, 먼저 안내에 나온 프로덕션 상태 요건에 맞춰 설정합니다.

Google에 따르면 Testing 상태의 외부 앱이 Drive 권한 범위를 요청하면 갱신 토큰은 7일 뒤에 만료됩니다. 프로덕션 상태로 바꾸더라도 다른 이유로 토큰이 만료될 수는 있습니다. 자세한 내용은 Google의 토큰 만료 문서에 나와 있습니다.

설정 마법사를 실행합니다. 

rclone config

저장소 유형을 drive 로 선택하고 gdrive 라는 원격 저장소를 만듭니다. 직접 만든 클라이언트의 인증 정보를 입력한 뒤 브라우저에서 접근을 승인합니다. 이미 설정한 원격 저장소라면 마법사에서 인증 정보를 수정하고 토큰을 교체합니다. 기존 원격 저장소 이름은 그대로 둡니다. rclone 설정 안내를 참고합니다.

기존 파일을 읽기만 한다면 drive.readonly 를 선택합니다. 쓰기도 필요하면 drive 를 선택합니다. drive.file 은 기존의 모든 파일에 접근할 수 있는 권한이 아닙니다. 이 권한은 Google이 rclone에 부여하는 것으로, 마운트할 때 쓰는 --read-only 옵션과는 별개입니다. Google의 권한 범위 설명에서 차이를 확인할 수 있습니다.

터미널에서 접근하기

아래 명령은 마운트 없이 원격 저장소에 직접 접근합니다. 

rclone listremotes
rclone lsf gdrive: --max-depth 1
rclone lsf 'gdrive:some-folder' --max-depth 1

공백이 들어간 경로는 셸에서 따옴표로 감싸야 합니다. 일반 텍스트 파일 하나를 읽으려면 다음과 같이 실행합니다. 

rclone cat 'gdrive:some-folder/example.txt'

설정을 마친 컴퓨터에서는 어느 터미널에서든 원격 저장소를 사용할 수 있습니다. 다른 컴퓨터에서는 rclone을 설치하고 그 컴퓨터에서도 설정과 인증을 해야 합니다. 브라우저가 없는 서버에서는 브라우저 인증 질문에 no라고 답한 뒤, 브라우저가 있는 컴퓨터에서 마법사의 안내를 따릅니다. rclone의 원격 설정 안내를 참고합니다.

rclone config file 로 설정 파일의 위치를 확인할 수 있습니다. 이 파일에는 토큰이 들어 있으므로 민감한 정보로 다뤄야 합니다. 블로그에 붙여 넣거나 Git에 커밋하지 않습니다. 예제, 스크린샷, 명령 기록에도 인증 정보가 남지 않도록 주의합니다.

파일 경로가 필요한 도구를 위해 마운트하기

저는 ~/gdrive 에 마운트합니다. 우선 읽기 전용으로 시작합니다. 

mkdir -p ~/gdrive
rclone mount gdrive: ~/gdrive --read-only --vfs-cache-mode full

이 명령은 포그라운드에서 계속 실행됩니다. 마운트를 사용하는 동안 터미널을 열어 둡니다.

AI 에이전트에는 읽기 전용 접근부터

에이전트가 문서를 읽기만 하면 된다면 --read-only 가 유용한 안전장치입니다. 이 마운트를 통해서는 파일을 덮어쓰거나 삭제할 수 없습니다. 다만 내용을 읽고 복사할 수는 있으므로 정보 유출까지 막아 주지는 않습니다.

여기서 중요한 점은 읽기 전용 마운트가 샌드박스는 아니라는 것입니다. 쓰기 권한이 있는 rclone 인증 정보에 접근할 수 있는 에이전트는 rclone을 직접 호출해 이 제한을 우회할 수 있습니다. 더 확실히 분리하려면 읽기 전용 인증 정보만 주고, 전체 권한을 가진 설정에는 접근하지 못하게 해야 합니다. 예를 들어 별도의 OS 사용자로 실행할 수 있습니다. 원격 저장소를 하나 더 만들고 이름만 "readonly"로 붙이는 것으로는 부족합니다.

쓰기도 가능한 백그라운드 마운트

제가 직접 사용할 때는 파일을 수정할 수도 있어야 합니다. 이미 마운트되어 있다면 먼저 해제하고, 이번에는 --read-only 를 빼고 실행합니다. 

mkdir -p ~/gdrive ~/.local/state/rclone
rclone mount gdrive: ~/gdrive \
  --vfs-cache-mode full \
  --daemon \
  --log-file ~/.local/state/rclone/gdrive.log \
  --log-level INFO

gdrive 를 drive.readonly 권한으로 인증했다면 rclone config 에서 수정해야 합니다. 권한 범위를 drive 로 바꾸고 다시 인증합니다. 마운트 옵션을 빼는 것만으로 Google이 부여한 권한이 늘어나지는 않습니다. 다른 사람이 읽기 전용으로 공유한 파일을 수정할 수 있게 되는 것도 아닙니다.

쓰기가 가능하다는 것은 수정, 이름 변경, 삭제가 실제 Drive 파일에 반영될 수 있다는 뜻입니다. 이 폴더를 사용하는 에이전트의 작업도 마찬가지입니다. 그런 접근 권한을 주기 전에 이전 버전을 보관하는 백업을 마련해 둡니다.

--daemon 은 마운트를 백그라운드에서 실행합니다. 재부팅 뒤 자동으로 시작하거나 비정상 종료 뒤 다시 실행해 주는 설정은 아닙니다. 로그는 ~/.local/state/rclone/gdrive.log 에 남습니다. 같은 방식으로 백그라운드에서 읽기만 하려면 --read-only 를 다시 추가합니다.

VFS 캐시를 사용할 때는 로컬에 저장했다고 해서 업로드까지 끝난 것은 아닙니다. 파일을 닫고 업로드 대기 시간이 지나야 하므로, 종료 전에 로그를 확인합니다. 자세한 동작은 rclone 마운트 문서를 참고합니다.

마운트 해제와 끊어진 마운트 복구

마운트가 정상이라면 쓰기 작업을 마친 뒤 다음 명령으로 해제합니다. 

fusermount -u ~/gdrive

폴더에 접근할 때 Transport endpoint is not connected 가 나오고 마운트 프로세스도 종료된 상태라면, 남아 있는 마운트를 먼저 분리한 뒤 다시 마운트합니다. 

fusermount -uz ~/gdrive

이 명령은 마운트를 분리할 뿐, Drive 파일을 삭제하지는 않습니다. 아직 업로드하지 못한 데이터를 전송하는 명령도 아닙니다. 배포판에 따라 명령 이름이 fusermount3 일 수 있습니다.

Google 문서 형식의 파일

Google 문서 형식의 파일에 접근하면 내보낸 사본을 보게 됩니다. 이렇게 내보낸 파일을 여는 것은 Google Docs에서 실시간으로 편집하는 것과 다릅니다. Google의 내보내기 문서를 참고합니다. rclone 문서에 따르면 이런 파일은 마운트에서 크기가 0바이트로 표시될 수 있습니다. 마운트로 접근할 수 없다면 직접 다운로드합니다. rclone의 Google Docs 제한 사항에 설명되어 있습니다.

마운트, 복사, 동기화의 차이

제가 원한 것은 마운트해서 사용하는 방식입니다. 마운트는 프로그램이 파일을 사용할 때 원격 저장소의 파일 내용을 가져옵니다. 캐시가 있다고 해서 모든 파일의 오프라인 사본이나 백업이 생기는 것은 아닙니다.

작업 용도 삭제 동작
mount 원격 파일을 폴더로 제공 쓰기 작업이 Drive에 반영됨
copy 새 파일이나 변경된 파일을 전송 대상에만 있는 파일은 삭제하지 않음
sync 대상을 원본과 같게 맞춤 대상에만 있는 파일을 삭제할 수 있음
bisync 양쪽의 변경 사항을 맞춤 삭제가 양방향으로 전파될 수 있음

폴더를 다운로드하려면 먼저 실제로 파일을 옮기기 전에 어떤 작업을 할지 확인합니다. 

rclone copy 'gdrive:some-folder' ~/DriveDownloads/some-folder --dry-run

원본과 대상 경로가 의도한 곳이 맞으면 --dry-run 을 빼고 실행합니다. copy는 대상 파일이 원본과 다르면 덮어쓸 수 있습니다. 대상에만 있는 파일을 남겨 둔다고 해서 이전 버전까지 보관하는 것은 아닙니다. copy, sync, bisync 문서에서 각 동작을 확인할 수 있습니다.
