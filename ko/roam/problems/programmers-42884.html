programmers-42884 — 단속카메라

출처

프로그래머스 42884 — 단속카메라

문제

링크된 문제의 요약입니다. 각 차량은 고속도로의 진입 지점부터 진출 지점까지 이동합니다. 차량별 이동 경로가 주어지면 모든 차량이 경로에서 카메라를 적어도 한 번 만나도록 하는 데 필요한 최소 카메라 수를 반환합니다.

제약 조건

  • 차량은 1대 이상 10,000대 이하입니다.
  • routes[i][0] 은 차량 i 의 진입 지점이고, routes[i][1] 은 진출 지점입니다.
  • 진입 지점이나 진출 지점에 카메라가 있어도 만난 것으로 봅니다.
  • 진입 지점과 진출 지점은 모두 -30,000 이상 30,000 이하입니다.

예시

routes return
[[-20,-15], [-14,-5], [-18,-13], [-5,-3]] 2

-15와 -5에 카메라를 설치하면 네 차량을 모두 단속할 수 있습니다. -15의 카메라는 첫 번째와 세 번째 경로를 지나는 차량을, -5의 카메라는 두 번째와 네 번째 경로를 지나는 차량을 단속합니다.

풀이

#include <vector>
#include <algorithm>

using namespace std;

int solution(vector<vector<int>> routes) {
    sort(routes.begin(), routes.end(), [](const vector<int>& a, const vector<int>& b) {
        return a[0] < b[0];
    });

    int answer = 1;
    int limit = routes[0][1]; 

    for (const auto& r : routes) {
        if (r[0] > limit) {
            answer++;
            limit = r[1]; 
        } else {
            limit = min(limit, r[1]);
        }
    }
    return answer;
}

처음 접근

#include <string>
#include <vector>
#include <algorithm>

using namespace std;

bool check_overlap(vector<int>& range1, const vector<int>& range2) {
    if (range1[1] < range2[0]) {
        range1 = range2;
        return false;
    }
    else {
        range1 = {range2[0], range1[1]};
        return true;
    }
}

int solution(vector<vector<int>> routes) {
    int answer = 0;
    sort(routes.begin(), routes.end(), [](const vector<int>& a, const vector<int>& b) {
        return a[0] < b[0];
    });
    vector<int> range = {-90000, -60000};
    for (const auto& r : routes) {
        bool overlap = check_overlap(range, r);
        if (overlap == false) answer++; 
    }
    return answer;
}

처음에는 이렇게 풀었습니다. 구간 전체를 계속 저장하면서 불필요한 상태도 유지하고 있습니다.

돌아보며

정렬하면 풀린다는 것 외에는 왜 먼저 정렬해야 하는지 설득력 있게 설명하지 못했습니다. 어떤 불변식을 유지할 수 있기 때문이라는 직감은 있었지만, 그 불변식이 무엇인지는 알지 못했습니다.

조금 더 생각해 보니 이유를 설명할 수 있습니다. 현재 묶음에 속한 경로들의 공통 구간을 R, 다음 경로를 A라고 하겠습니다. 진입 지점 순으로 정렬한 경우와 정렬하지 않은 경우를 비교해 봅니다. 정렬했다면 A가 R과 겹치지 않을 때 남은 경로도 모두 R과 겹치지 않는다고 판단할 수 있습니다. 남은 경로의 진입 지점은 모두 A의 진입 지점 이상이기 때문입니다. 따라서 현재 묶음을 마무리하고 A를 새로운 R로 삼아 다시 시작할 수 있습니다. 정렬하지 않았다면 A와 비교한 결과만으로 남은 경로에 대해 같은 판단을 내릴 수 없습니다.

정렬하면 경로들을 처리가 끝난 부분, 현재 처리 중인 부분, 아직 처리하지 않은 부분으로 나누어 볼 수 있습니다. 현재 경로를 처리한 결과를 바탕으로 아직 처리하지 않은 부분의 성질을 추론할 수 있습니다.

최적화한 풀이가 더 짧다는 것은 알지만, 문제를 구성한 방식 자체는 마음에 들지 않습니다. 실제로 이런 문제를 해결한다면 보통 카메라 수뿐 아니라 설치할 구간도 찾아야 합니다. 알고리즘 문제 풀이가 실제 쓰임과 동떨어져 있다는 점은 제 취향과 조금 맞지 않습니다.
