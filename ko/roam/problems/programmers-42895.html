programmers-42895 — N으로 표현

출처

프로그래머스 42895 — N으로 표현

문제

링크된 문제의 요약입니다. 한 자리 숫자 N 과 목표값 number 가 주어지면, 목표값을 표현하는 데 필요한 N 의 최소 사용 횟수를 반환합니다. 같은 숫자를 이어 붙이거나 괄호와 덧셈, 뺄셈, 곱셈, 나눗셈을 사용할 수 있습니다. 나눗셈에서는 나머지를 버립니다. 최소 사용 횟수가 여덟 번을 넘으면 -1을 반환합니다.

제약 조건

  • 1 < N <= 9=
  • 1 < number <= 32000=
  • 수식에 괄호와 사칙연산을 사용할 수 있으며, N = 5 일 때 55처럼 N 을 이어 붙인 수도 사용할 수 있습니다.

예시

N number 반환값
5 12 4
2 11 3

첫 번째 예시에서는 (55 + 5) / 5 로 5를 네 번 사용해 12를 표현합니다. 두 번째 예시에서는 22 / 2 로 2를 세 번 사용해 11을 표현합니다.

풀이

#include <string>
#include <vector>
#include <unordered_set>

using namespace std;

int solution(int N, int number) {
    int answer = 0;
    vector<unordered_set<int>> dp(9);

    int tmp = 0;
    for (int i = 1; i < 9; i++) {
        tmp = tmp * 10 + N;
        dp[i].insert(tmp);
    }

    for (int k = 1; k<9;k++){
        for (int i = 1; i < k; i++) {
            int j = k - i;
            for (int a : dp[i]) {
                for (int b : dp[j]) {
                    dp[k].insert(a+b);
                    dp[k].insert(a-b);
                    dp[k].insert(a*b);
                    if (b != 0) dp[k].insert(a/b);
                }
            }
        }

        if (dp[k].count(number) != 0) return k;
    }


    return -1;
}

접근 방법

처음에는 경우의 수가 지수적으로 늘어나 이 방식으로는 풀기 어렵다고 생각했습니다. \(9^8=3^{16}\) 을 떠올렸지만, 이 추정은 실제 구현에서 처리하는 조합을 센 것이 아닙니다.

이 풀이는 만들 수 있는 값들을 집합에 저장하는 동적 계획법입니다. dp[k] 에는 N 을 정확히 k 번 사용해 표현할 수 있는 서로 다른 정수를 저장합니다. 먼저 55처럼 같은 숫자를 이어 붙인 수를 넣습니다. 그런 다음 k = i + j 로 나누는 모든 경우에 대해 dp[i] 와 dp[j] 에 저장된 값들을 사칙연산으로 조합합니다. 이때 0으로 나누는 경우는 건너뜁니다. 서로 다른 수식이라도 결과가 같으면 집합에는 값 하나만 남습니다. 사용 횟수를 늘려 가며 목표값이 집합에 있는지 확인합니다.

정리

값의 크기, 상태 수, 연산량의 차이

\(N^8\) 은 N 여덟 개를 곱해서 만들 수 있으므로 dp[8] 에 들어갈 수 있는 값입니다. 집합의 원소 수를 뜻하지는 않습니다. 예를 들어 1과 1,000,000이 들어 있는 집합의 원소는 두 개뿐입니다. 한 번 실행하는 동안 숫자 N 은 고정되어 있으므로, 매 단계에서 선택지가 아홉 개씩 생기는 것도 아닙니다.

살펴봐야 할 것은 각 단계에 서로 다른 값이 몇 개 저장되고, 그 값들을 몇 쌍 조합하는지입니다. 중복된 수식을 처리할 때도 삽입은 시도하지만, 결과가 중복되면 이후 조합에 사용할 상태가 늘어나지는 않습니다. 따라서 가능한 수식의 수가 커 보인다고 해서 그 수가 곧 프로그램의 상태 수나 연산 횟수가 되는 것은 아닙니다.

저장된 상태 수로 보는 시간과 공간 복잡도

최대 사용 횟수를 \(K\) 라고 하면 이 문제에서는 8이며, 각 집합의 크기는 \(S_k=|dp[k]|\) 로 둡니다. \(k=i+(k-i)\) 로 나누는 경우마다 중첩 반복문은 \(S_iS_{k-i}\) 개의 값 쌍을 처리합니다. 각 쌍에 대해 최대 네 번 삽입을 시도합니다. 고정 폭 정수 연산을 사용하고 해시 연산의 분할상환 기대 시간이 상수라고 가정하면, \(K\) 단계까지의 시간 복잡도는 다음과 같습니다.

\[ O\left(K+\sum_{k=2}^{K}\sum_{i=1}^{k-1}S_iS_{k-i}\right). \]

모든 단계의 집합을 계속 저장하므로 공간 복잡도는 다음과 같습니다.

\[ O\left(K+\sum_{k=1}^{K}S_k\right). \]

\(S=\max_{1\le k\le K}S_k\) 로 두면, 더 느슨한 상한으로 시간 복잡도는 같은 해시 연산 가정 아래 \(O(K^2S^2)\), 공간 복잡도는 \(O(KS)\) 로 잡을 수 있습니다. 이 식들이 집합의 크기가 \(K\) 에 대해 다항식으로 증가함을 보장하지는 않습니다. 연산량이 각 집합에 저장된 상태 수에 어떻게 의존하는지 보여 줍니다. 목표값을 일찍 찾으면 여덟 단계의 조합을 모두 처리하기 전에 반환합니다.

\(3^{16}=43{,}046{,}721\) 이지만, 이 구현의 연산 횟수를 계산해 얻은 수는 아닙니다. 수백만 번의 연산을 감당할 수 있는지는 각 연산이 무엇을 하는지에도 달려 있습니다. 해시 삽입은 단순 덧셈보다 비용이 큽니다. 여기서는 집합의 크기나 실행 시간을 측정하지 않았습니다.
